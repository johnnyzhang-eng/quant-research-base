# Quant Research Base

一个以数据口径、已知答案、独立核账和实验留痕为基础的量化研究项目。当前是 **v0.4 验收基底**，尚未完成真实历史策略收益验证和官方模拟交易链路。

本项目复用现有引擎，研究规范与证据留在引擎外：数据/协议 → 仪器验收 → 主回测路径 → 独立核账/基准 → 向前验证。

## 当前可运行

- 严格研究配置：未知条件显式保留，拒绝重复 JSON 字段、非有限数字和不支持的运行目的。
- 净账户指标与开发段风险校准：现金流、初始证券、未定义比率、双边换手及费用口径；12个指标控制随统一入口运行，101个合成风险校准点保留。
- 独立运行目录、输入与源码快照、哈希封存、全部开始/结束记录、复跑指纹和篡改检测。
- 39 项合成参照控制；有限时点、费用、分红应收/支付、拆股与结算样例，含独立事件回放。
- 可选的本机 Vibe US-equity 路径对照：21 个共同合成样例；显式账户适配涵盖分红应收/支付、整数拆股、现金与股票结算，并经独立核账。
- 冻结的四 ETF 毛总收益/SMA10信号与 S/B0/BR/BC 合成账户路径；11个分配/完整路径样例和2个未来扰动控制。逐笔买单、先前成交量约束及缺开盘时的过去估值已显式建模。
- 已有 S02 四 ETF 快照的本地审计适配器；原始/派生数据不随仓库发布。
- 发布前的文件范围与凭证/私有路径检查。

第二阶段新增入口与验收方法见 [PHASE2](docs/PHASE2.md)：版本化历史输入转换、持久化离线模拟订单管理及独立封存入口。因果信号、按日期生效的费用/结算、人民币/美元现金利息和换汇已接入独立的[完整人民币账户模型](docs/historical-account.md)，保留来源标签并经 Fraction 逐事件复算。`phase2-controls --integrated-account-controls` 沿实际本机 Vibe 路径运行虚构已知答案；`account-run` 保存单个私有条件模型的输入、账本和复算。

[`study-run`](docs/historical-study.md) 保留开发段 101 个风险候选与冻结选择，再运行 S/B0/BR/BC × 两档本金 × 四种成本情景的 32 个连续账户；分段和年度报告保留原期初状态，并列全账户 CNY/USD、固定费用负债、破产记录、配对月度统计和单独退出分支。额外摩擦按固定网格重跑完整账户，保留份额与交易路径变化。较短虚构控制仅验计算程序；真实历史研究、原协议历史完整矩阵及官方模拟生命周期尚未完成。

独立的 [OpenD 模拟适配层](docs/futu-paper-adapter.md) 提供显式账户绑定、SQLite 请求留痕和查询恢复，依赖调用方注入已核对的传输对象；构造和导入不自动连接或发送。`paper-local-readiness` 仅检查私有配置及当前环境是否可发现 SDK。完整官方成交和费用核账仍待外部验证。

## 快速复现

macOS/Linux，Python 3.12+。默认命令只用标准库，不需要行情账号或安装交易框架。

```bash
python -B -m unittest discover -s tests -v
python -B -m research_base run --spec examples/validation.json --output runs-local
```

命令输出具体运行目录。将它传给封存检查：

```bash
python -B -m research_base verify PATH_TO_RUN --registry runs-local/registry.jsonl
```

已有 Vibe 环境时，可用该环境的 Python 运行：

```bash
python -B -m research_base run --spec examples/validation.json --output runs-local --vibe-controls
```

这条可选路径不会自动安装依赖或获取行情。被测引擎源码哈希、numpy/pandas版本和逐事件差异会保存到本地。兼容性以实际来源和控制记录为准。

默认测试环境明确跳过需要Vibe的集成测试；已有Vibe的本机环境可执行这些测试。各轮实际执行与跳过数量以该轮日志为准。GitHub默认CI不安装Vibe，不能据此宣称引擎集成已在远端验证。见[账户适配模型](docs/ACCOUNTING_MODEL.md)、[指标口径](docs/METRICS.md)、[完整协议路径](docs/PROTOCOL_PATH.md)与[配对月度检验](docs/PAIRED_INFERENCE.md)。

固定配对月度增长与循环区块bootstrap程序已接入统一入口，归档6个合成账户验收、4个坏输入拒绝及完整抽样位置/结果。它保留破产和缺月，不能从一个窗口或合成区间推导策略支持。

每次运行另输出[历史研究预检](docs/HISTORICAL_READINESS.md)，把不可变快照声明、本轮测量和D01–D06剩余条件分别记录。合成验收、完整性哈希或手改“ready”标签都不能授权历史试验。

`VALIDATION_COMPLETED_WITH_GAPS` 表示有限检查完成且仍有缺口。它不代表数据已适合历史研究、策略盈利或账户可执行。运行错误、配置拒绝和策略表现分别分类。

## 四个目标

1. **G1 共同入口**：契约、冻结输入、复现和全部试验记录。
2. **G2 数据与仪器**：来源/单位/时点/公司行动审计，控制沿真实使用路径验收。
3. **G3 首个研究**：冻结的四 ETF 低频规则，与同口径简单持有和风险匹配基准比较；条件缺失时明确报告，不能制造结果。
4. **G4 可持续公开**：代码、合成数据、方法和可发布证据持续交付；私有研究分离。

完整验收条件与未解决项见 [GOALS](docs/GOALS.md)、[研究规范](docs/RESEARCH_STANDARD.md)、[当前验收](docs/VALIDATION.md)。

## 公开边界

默认运行结果不进入 Git。凭证、账户材料、受限行情、潜在高价值因子、参数、信号和可反推出规则的结果，放在仓库外。只手工审核后导出允许公开的材料。忽略文件不是保密边界；详见[发布政策](docs/PUBLICATION.md)。

本仓库不包含真实供应商数据、不自动采集，也不把合成控制统计解释为投资收益。
