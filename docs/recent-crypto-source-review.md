Crypto-Strategies 的固定提交有 416 个策略源码和 416 份卡片，其中 10 个源码在 passed 目录。index 只有 406 条，均对应 rejected 源码；十份 passed 卡片均记录 stages_passed=2，所列收益及 Sharpe 均为负。README 的“全部七阶段通过”与这些字段尚需解释：卡片可能记录早期阶段，而私有日志包含后续结果。负值本身不证明后续验证失败。公开树没有独立验证器；不能据此承诺这些策略能盈利，也不能用其五分钟结果裁定我们不同日线协议的表现。[固定来源](https://github.com/CacheCarti/Crypto-Strategies/tree/f8e32599c192b823dbe7aea77a2b9341c6114527)

walk-forward-crypto 的固定公开树有 22 个文件，没有 Python 源码；其披露说明把参数、候选列表和策略实现保留在另一私有仓。因此，目前检查的公开证据尚不支持精确复现作者结果；这不等于证明近似重建不可能，或判定私有策略无效。[作者披露](https://github.com/AKzar1el/walk-forward-crypto/blob/8ec32ea1ad454edd88abc5118a808c6fa764063b/docs/REDACTION_REPORT.md)

论文的可迁移假设是：只有预测幅度足以覆盖换仓成本时才改变仓位。它也报告未能在调整后的检验中显著优于持有基准。数据章节称 Binance USD-M futures 从 2017-12 开始，官方公告则记载该业务 2019-09 上线；产品名称、拼接历史或数据端点需要澄清。当前未取得作者代码和原始数据。[论文](https://arxiv.org/html/2606.00060v1)，[官方上线公告](https://www.binance.com/en/support/announcement/detail/360033314152)

本机核查脚本用 10 组已知答案控制验证计数、重复键、完整树与 Markdown 口径，并将 16 份实际读取的捕获逐一匹配固定提交的 Git blob。独审用另一套 JSON、Fraction 和 Git blob 计算逐项确认数量与卡片字段；其捕获映射采用仓库、版本和路径，避免同名 README 被机器混淆。两份源码的导入摘要仅列 ImportFrom，普通 math 导入另记于独审。没有运行外部策略代码，也没有完成作者收益复现。

后续实验应先固定数据与费用口径，再比较成本过滤规则、原规则和持有基准。论文的过滤规则也可能在小幅负预测时保持原有多头，因此独立风险退出必须另行定义。该论文的预测幅度不是当前 Donchian 二值信号，不能直接把其参数或作者年化收益移入当前策略。
